# Reflection

AI has done a great job in not only translating the program but also making sure that the program has the right behavior. The astunning part of it is that given the ATS program with the correct behavior, it translates the program into python in incredibly fast speed. On the other hand, AI completely follows the instructions in a precise manner, which means AI can be well-used to make large projects with clear instructions.

But it also comes with huge drawbacks: 
1. Without clear instrucions, AI might edit files/create unwanted dir/files to accomplish its goal
2. Without human knowledge, AI always tries the hard way, for example, write a completely new c file to test if the original program written in ATS, whereas in reality it could be done using an ATS compiler. 
3. AI translation keeps the ambiguity of function names in the original program, like security check 1 and security check 2, instead of commenting on them/give the functions more descriptive names.
4. It can often be hard for AI to correct itself - since the results from a prompt are mathematically optimal and similar to each other. This means that when AI makes a mistake, it can get very hard to fix the bug and often times resulting in rewriting more code than expected. However, this problem is not found in this assignment, where AI did clear and correct translation.

I couldn't understand code in ATS language, so I had to look a lot closer to the python translation of the program to understand how it ensures the correctness, and I also have to make sure that the original program eight_queens.dats was correct so that the AI translation of that program is also correct. Additionally, I also added some md files to record AI suggestions to understand it better, and finally a testing file that includes several test cases with an N_queens test where N > 8 to make sure the program runs correctly on edge cases. 

But AI coding shouldn't be trusted without testing, as testing is a core step to verify what specification has been carried out correctly. Sometimes it is not about the correctness but about bridging the dismatched instructions. Human languages are in their nature ambiguous, and sometimes the ambiguous commands map to several different interpretations on how to solve a problem. Thus, testing is always a necessary step verify if the commands are satisfied on at least a very small set of scenarios. Without testing, the intructions could be misinterpreted, not to mention that bugs in code will be ignored in that case. 

AI has a huge impact on my workflow as I tend to ask more and more questions using AI before I even start writing my code. Most CS students end up trying to have perfect algorithms and for me it is also true that I want to always be using the best practices in the industry, for a tiny example, standard naming convention. And thus I ask AI a lot about the "best way to do things". Which has influnced my coding style and workflow implicitly. In terms of the amount of work, AI doesn't necessary bring it down a lot, as it is also bringing this need to review, check, and test the code by humans themselves as they finish a part of human jobs.
